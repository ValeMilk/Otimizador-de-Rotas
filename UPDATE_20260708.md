## 🐛 Bug Corrigido: Travel Time Allocation

### Problema Original
Routes estavam ultrapassando a capacidade diária ao combinar tempo de serviço + deslocamento.

**Exemplo**:
```
RAFAEL / Segunda-feira:
  Tempo de Serviço:        7h 49m
  Tempo de Deslocamento:   58m
  Total:                   8h 47m ❌ (ultrapassa 8h)
```

### Root Cause
Função `tentarAlocarEmDia()` em `utils/dynamicRouteGenerator.ts` verificava apenas `visitDurationMinutes` contra capacidade, ignorando tempo de deslocamento.

### Solução Implementada
**Buffer-Based Verification Strategy** (linhas 406-445 de dynamicRouteGenerator.ts):

```typescript
// 1. Buffer conservador durante alocação
const tempoDeslocamentoBuffer = visitasNoDia.length === 0 ? 8 : 3;

// 2. Verificação: Pode alocar?
const tempoTotalNecessario = tempoVisita + tempoDeslocamentoBuffer;
if (tempoTotalNecessario > capacidadeDisponivel) return false;

// 3. Contabilização: Apenas tempo real (sem buffer)
agenda[dia].tempoUsado += tempoVisita;  // Buffer NÃO é contado
```

**Key Points**:
- ✅ Buffer usado APENAS para verificação de feasibility
- ✅ Alocação conservadora (não aloca se não couber com buffer)
- ✅ Tempo contabilizado é APENAS tempo de visitação
- ✅ Cálculos precisos durante construção de rota (OSRM)

## 🔍 Detalhes Técnicos

### Arquivo Modificado
- **Path**: `utils/dynamicRouteGenerator.ts`
- **Função**: `tentarAlocarEmDia()` (linhas 406-445)
- **Mudanças**: Buffer de deslocamento adicionado durante verificação de capacidade

### Buffer Values
- **Primeiro cliente**: 8 minutos (inclui trajeto casa→cliente→casa)
- **Clientes subsequentes**: 3 minutos (trajeto inter-cliente)
- **Multiplier Haversine**: 1.5x (se OSRM indisponível)

### Strategy Pattern
```
Alocação (Conservadora):  Buffer + Verificação → não aloca se não couber
Construção (Precisa):     OSRM/Haversine → tempos reais sem buffer
Contabilização:           Apenas visitação → sem dupla-penalização
```
